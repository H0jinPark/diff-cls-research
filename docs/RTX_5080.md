# RTX 5080 실험 실행 안내

이 설정은 **Linux x86-64 + NVIDIA RTX 5080**을 가정한다. 서버에 적합한 드라이버와 GPU 할당이 필요하다. 다른 OS·아키텍처인 경우 PyTorch 공식 설치 선택기를 확인한다. 이 프로젝트는 서버에 접속하거나 GPU에서 검증한 적이 없다.

## 데이터와 코드

GitHub 저장소에는 코드와 합성 데모만 들어 있다. Tratz 기반 실험 데이터는 아래 명령으로 PANIC 저장소에서 별도로 받는다.

```bash
git clone https://github.com/H0jinPark/diff-cls-research.git
cd diff-cls-research
```

기존 ZIP 번들을 이용하는 경우에는 대신 압축을 풀 수 있다. 공개 저장소에 원 데이터를 재업로드하기 전에 사용 조건을 확인한다.

## Conda와 CUDA PyTorch

```bash
conda env create -f environment-5080.yml
conda activate diff-cls-5080
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e '.[test]'
nvidia-smi
python scripts/check_cuda.py
pytest -q
```

PyTorch의 CUDA 12.8 wheel을 먼저 설치한다. 드라이버, 서버 GPU 배정, 공유 서버 정책에 따라 관리자 설정이 필요할 수 있다. `check_cuda.py`는 GPU에서 실제 행렬곱을 수행하므로, 단순히 GPU가 보이는지만 확인하지 않는다. 서버에 다른 PyTorch를 이미 설치했다면 버전을 확인하고 혼합 환경을 피한다.

## Tratz 데이터 준비

```bash
bash scripts/prepare_tratz_5080.sh
```

PANIC 공개 저장소를 `data/benchmarks/panic`에 받고 로컬 실험에 사용한 커밋 `9f7556eab0daf98698dba6f4b13b4668b45ba928`로 고정한다. 원본 train/val/test의 SHA-256을 검증하고 분할을 보존하여 `data/splits/tratz-coarse-lexical`에 변환한다. 기존 소스가 다른 커밋이거나 결과 디렉터리가 비어 있지 않으면 덮어쓰지 않고 중단한다. 변환 결과는 Git에서 제외된다. 원 데이터와 코드의 이용 조건을 확인한다.

## 검증 실험

```bash
bash scripts/run_5080.sh
```

사전학습 영어 `google-bert/bert-large-uncased`(최초 다운로드 필요), CL 없음, 20 epoch, 3 seed, batch 8, CUDA. 다음 세 가지 입력을 공통 BERT와 같은 MLP 폭으로 비교한다.

1. 기존 최고 검증 설정 `diff_cls`: `[DIFF] - [CLS]` (1024차원).
2. `cls_cls`: 복합어 CLS - 기본어 CLS (1024차원).
3. `pair_interaction`: `[DIFF]; [CLS]; |DIFF-CLS|; DIFF*CLS` (4096차원).

모델별 첫 FC 입력 차원이 다르므로 파라미터 수가 다르다. `pair_interaction`은 더 큰 헤드이므로 개선을 구조적 효과로만 단정할 수 없다. 서로 다른 학습량을 초래하는 CL은 비활성화한다. dev 최고 Macro-F1 epoch를 선택하며 **test는 사용하지 않는다**. Accuracy/Macro-F1/Weighted-F1도 기록한다. 동일 조건에서 test 결과와 논문 결과를 비교하기 전 metric 및 평가 프로토콜을 확인할 것.

예상 VRAM 사용량은 실제 환경에 따라 다르다. OOM이면 새 output을 사용하여 `BATCH_SIZE=4 bash scripts/run_5080.sh`로 다시 실행한다. batch 변경은 최적화 조건도 바꾸므로 비교 실험에서 모든 모델에 동일하게 적용한다. `EPOCHS`, `SEEDS`, `MODEL_ID`, `OUTPUT_DIR`도 환경 변수로 지정 가능하다. 중간 중단 뒤 자동 resume은 지원하지 않는다.

빠른 파이프라인 점검: `EPOCHS=1 SEEDS=42 bash scripts/run_5080.sh`. 본 실험과 다른 조건임을 명시한다. 학습된 가중치는 `runs/` 아래 생성되며 Git에 포함하지 않는다.

## 전체 실험을 nohup으로 실행

기존 실험이 같은 GPU를 사용 중이라면 완료 또는 중단 여부를 먼저 확인한다. 아래 명령은 기존 작업을 중단하지 않는다. Conda 환경이 활성화된 상태에서 실행한다.

```bash
mkdir -p runs
RUN_ID="overnight-$(date +%Y%m%d-%H%M%S)"
nohup env OUTPUT_DIR="runs/$RUN_ID" bash scripts/overnight_5080.sh \
  > "runs/$RUN_ID.log" 2>&1 < /dev/null &
echo "PID=$!  LOG=runs/$RUN_ID.log  OUTPUT=runs/$RUN_ID"
```

위 `RUN_ID`는 이 셸 변수다. 다른 터미널에서는 `ls -t runs/overnight-*.log | head`로 로그 이름을 확인하고 아래 예시의 경로를 바꾼다.

```bash
tail -f runs/overnight-YYYYMMDD-HHMMSS.log
```

기본은 8개 모델 설정 × 3 seed × 분류 20 epoch이며, CL 적용 두 설정에는 각 3 epoch가 추가된다. `diff_cls`, `cls_cls`, `concat_cls`, `pair_interaction`, `diff_only`, `modifier_only`, 그리고 `diff_cls_cl`, `concat_cls_cl`이다. 기존에 검토한 CL은 positive head와 raw embedding 기준이며, freeze하지 않는다. `EPOCHS`, `BATCH_SIZE`, `SEEDS`, `CONTRASTIVE_EPOCHS`, `MODEL_ID`를 nohup 앞의 `env`로 조정할 수 있다.

학습 종료 후 **사전에 고정한 모든 모델**을 테스트하므로 테스트 성적에 근거해 다시 모델을 선택하면 더 이상 독립적인 최종 평가가 아니다. 중간 결과는 `train-progress.json`, 최종 결과는 `paper-results.json`에 기록된다. 실패 시 로그와 완료된 폴더는 남지만 자동 재개는 지원하지 않는다. 원본 PANIC의 체크포인트 선택 및 테스트 방식처럼 **weighted F1**을 사용하고 정확도와 macro F1도 함께 계산한다. 원 논문의 early stopping, 외부 데이터와 모델은 다르므로 완전 재현은 아니다. 0.478은 2018년 논문 결과이고 최신 SOTA를 보증하지 않는다.
