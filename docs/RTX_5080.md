# RTX 5080 실험 실행 안내

이 설정은 **Linux x86-64 + NVIDIA RTX 5080**을 가정한다. 서버에 적합한 드라이버와 GPU 할당이 필요하다. 다른 OS·아키텍처인 경우 PyTorch 공식 설치 선택기를 확인한다. 이 프로젝트는 서버에 접속하거나 GPU에서 검증한 적이 없다.

## 데이터와 코드

GitHub 저장소에는 코드와 합성 데모만 들어 있다. Tratz 기반 실험 데이터는 아래 명령으로 PANIC 저장소에서 별도로 받는다.

```bash
git clone https://github.com/H0jinPark/diff-cls-research.git
cd diff-cls-research
```

기존 ZIP 번들을 이용하는 경우에는 대신 압축을 풀 수 있다. 공개 저장소에 원 데이터를 재업로드하기 전에 사용 조건을 확인한다.

## Conda와 CUDA PyTorch

```bash
conda env create -f environment-5080.yml
conda activate diff-cls-5080
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -e '.[test]'
nvidia-smi
python scripts/check_cuda.py
pytest -q
```

PyTorch의 CUDA 12.8 wheel을 먼저 설치한다. 드라이버, 서버 GPU 배정, 공유 서버 정책에 따라 관리자 설정이 필요할 수 있다. `check_cuda.py`는 GPU에서 실제 행렬곱을 수행하므로, 단순히 GPU가 보이는지만 확인하지 않는다. 서버에 다른 PyTorch를 이미 설치했다면 버전을 확인하고 혼합 환경을 피한다.

```bash
bash scripts/prepare_tratz_5080.sh
```

PANIC 공개 저장소를 `data/benchmarks/panic`에 받고 로컬 실험에 사용한 커밋 `9f7556eab0daf98698dba6f4b13b4668b45ba928`로 고정한다. 원본 train/val/test의 SHA-256을 검증하고 분할을 보존하여 `data/splits/tratz-coarse-lexical`에 변환한다. 기존 소스가 다른 커밋이거나 결과 디렉터리가 비어 있지 않으면 덮어쓰지 않고 중단한다. 변환 결과는 Git에서 제외된다. 원 데이터와 코드의 이용 조건을 확인한다.

## 검증 실험

### 백본·마커 통제 실험

사전학습 BERT, 데이터, classifier 폭, 옵티마이저, seed와 검증 checkpoint 선택 기준을 고정해 표현 방법을 비교한다. 각 설정은 별도 미세조정되므로 가중치가 학습 후 같다는 뜻은 아니다.

| 설정 | 입력과 출력 표현 |
|---|---|
| `compound_cls` | `[CLS] modifier head [SEP]`의 CLS |
| `marked_cls` | `[CLS] modifier [DIFF] head [SEP]`의 CLS |
| `diff_only` | 위 마커 포함 입력의 DIFF |
| `marked_cls_diff` | 위 마커 포함 입력의 CLS − 기본어 CLS |
| `diff_cls` | 위 마커 포함 입력의 DIFF − 기본어 CLS |
| `diff_cls_cl` | 위 diff_cls에 대조학습 3 epoch를 추가 |

```bash
export HF_HOME="$PWD/.hf-cache"
RUN_ID="controls-$(date +%Y%m%d-%H%M%S)"
mkdir -p runs
nohup python -u scripts/backbone_controls.py \
  --output "runs/$RUN_ID" --device cuda > "runs/$RUN_ID.log" 2>&1 < /dev/null &
echo "PID=$! LOG=runs/$RUN_ID.log OUTPUT=runs/$RUN_ID"
```

기본 설정은 각 20 epoch와 seed 13/42/77로 총 18회 학습하고 CL은 `diff_cls_cl`에만 적용한다. 검증 weighted F1이 최고인 체크포인트 및 seed별 paired 차이를 저장하며 test를 읽지 않는다. 일부 표현은 BERT를 한 번, 다른 표현은 두 번 통과하고 CL에는 추가 학습이 들어가므로 총 계산량이 같다거나 CL만의 순수한 효과라고 주장할 수 없다. 마커가 다른 입력의 비교는 토큰 추가 효과와 문맥/위치 변화가 섞인다. **같은 백본 통제 실험은 사전학습 데이터 노출 여부나 LexNET과의 독립적인 비교를 증명하지 않는다.** test는 이미 실험에서 여러 설정에 사용돼 새 최종 검증셋이 아니다.

자동 재개는 지원하지 않으며 중단 시 완료된 체크포인트와 `summary.json`은 보존된다. 기존 결과 폴더는 덮어쓰지 않는다.

```bash
bash scripts/run_5080.sh
```

사전학습 영어 `google-bert/bert-large-uncased`(최초 다운로드 필요), CL 없음, 20 epoch, 3 seed, batch 8, CUDA. 다음 세 가지 입력을 공통 BERT와 같은 MLP 폭으로 비교한다.

1. 기존 최고 검증 설정 `diff_cls`: `[DIFF] - [CLS]` (1024차원).
2. `cls_cls`: 복합어 CLS - 기본어 CLS (1024차원).
3. `pair_interaction`: `[DIFF]; [CLS]; |DIFF-CLS|; DIFF*CLS` (4096차원).

모델별 첫 FC 입력 차원이 다르므로 파라미터 수가 다르다. `pair_interaction`은 더 큰 헤드이므로 개선을 구조적 효과로만 단정할 수 없다. 서로 다른 학습량을 초래하는 CL은 비활성화한다. dev 최고 Macro-F1 epoch를 선택하며 **test는 사용하지 않는다**. Accuracy/Macro-F1/Weighted-F1도 기록한다. 동일 조건에서 test 결과와 논문 결과를 비교하기 전 metric 및 평가 프로토콜을 확인할 것.

예상 VRAM 사용량은 실제 환경에 따라 다르다. OOM이면 새 output을 사용하여 `BATCH_SIZE=4 bash scripts/run_5080.sh`로 다시 실행한다. batch 변경은 최적화 조건도 바꾸므로 비교 실험에서 모든 모델에 동일하게 적용한다. `EPOCHS`, `SEEDS`, `MODEL_ID`, `OUTPUT_DIR`도 환경 변수로 지정 가능하다. 중간 중단 뒤 자동 resume은 지원하지 않는다.

빠른 파이프라인 점검: `EPOCHS=1 SEEDS=42 bash scripts/run_5080.sh`. 본 실험과 다른 조건임을 명시한다. 학습된 가중치는 `runs/` 아래 생성되며 Git에 포함하지 않는다.

## 전체 실험을 nohup으로 실행

기존 실험이 같은 GPU를 사용 중이라면 완료 또는 중단 여부를 먼저 확인한다. 아래 명령은 기존 작업을 중단하지 않는다. Conda 환경이 활성화된 상태에서 실행한다.

```bash
mkdir -p runs
RUN_ID="overnight-$(date +%Y%m%d-%H%M%S)"
nohup env OUTPUT_DIR="runs/$RUN_ID" bash scripts/overnight_5080.sh \
  > "runs/$RUN_ID.log" 2>&1 < /dev/null &
echo "PID=$!  LOG=runs/$RUN_ID.log  OUTPUT=runs/$RUN_ID"
```

위 `RUN_ID`는 이 셸 변수다. 다른 터미널에서는 `ls -t runs/overnight-*.log | head`로 로그 이름을 확인하고 아래 예시의 경로를 바꾼다.

```bash
tail -f runs/overnight-YYYYMMDD-HHMMSS.log
```

기본은 8개 모델 설정 × 3 seed × 분류 20 epoch이며, CL 적용 두 설정에는 각 3 epoch가 추가된다. `diff_cls`, `cls_cls`, `concat_cls`, `pair_interaction`, `diff_only`, `modifier_only`, 그리고 `diff_cls_cl`, `concat_cls_cl`이다. 기존에 검토한 CL은 positive head와 raw embedding 기준이며, freeze하지 않는다. `EPOCHS`, `BATCH_SIZE`, `SEEDS`, `CONTRASTIVE_EPOCHS`, `MODEL_ID`를 nohup 앞의 `env`로 조정할 수 있다.

학습 종료 후 **사전에 고정한 모든 모델**을 테스트하므로 테스트 성적에 근거해 다시 모델을 선택하면 더 이상 독립적인 최종 평가가 아니다. 중간 결과는 `train-progress.json`, 최종 결과는 `paper-results.json`에 기록된다. 실패 시 로그와 완료된 폴더는 남지만 자동 재개는 지원하지 않는다. 원본 PANIC의 체크포인트 선택 및 테스트 방식처럼 **weighted F1**을 사용하고 정확도와 macro F1도 함께 계산한다. 원 논문의 early stopping, 외부 데이터와 모델은 다르므로 완전 재현은 아니다. 0.478은 2018년 논문 결과이고 최신 SOTA를 보증하지 않는다.

## BiLSTM과 GloVe 비교 실험

동일한 Tratz train/dev와 weighted F1 체크포인트 선택을 사용한다. 네 조건은 `compound_mean` (마커 없는 복합어 토큰 hidden state 평균), `diff_only`, `diff_minus_base`, `diff_minus_base_cl`이다. 후자의 세 조건은 `modifier [DIFF] head`의 `[DIFF]` state를 읽으며, base는 중심어 토큰 hidden state 평균이다. BiLSTM은 패딩 영향을 제거하고, GloVe와 `[DIFF]`를 포함한 임베딩은 학습된다. CL은 같은 head 문자열을 양성으로 사용하는 기존 InfoNCE와 동일하며 encoder를 freeze하지 않는다. CL 조건에만 3 epoch가 추가된다.

Stanford GloVe 6B(2014 Wikipedia + Gigaword 5, 300차원)를 서버에 준비한다. ZIP은 약 822 MB이며 디스크 여유가 필요하다. 원본 벡터 이용 조건을 확인한다. 다운로드 중단이나 오류 시 기존 ZIP이 손상됐을 수 있으니 다시 받는다.

```bash
mkdir -p data/benchmarks/glove
curl -fL --retry 3 -o data/benchmarks/glove/glove.6B.zip https://nlp.stanford.edu/data/glove.6B.zip
unzip -n data/benchmarks/glove/glove.6B.zip glove.6B.300d.txt -d data/benchmarks/glove
```

이미 Tratz 데이터가 있으면 재다운로드할 필요 없다. 없으면 `bash scripts/prepare_tratz_5080.sh`를 먼저 실행한다.

```bash
conda activate diff-cls-5080
mkdir -p runs
RUN_ID="bilstm-$(date +%Y%m%d-%H%M%S)"
nohup python -u scripts/bilstm_controls.py \
  --glove data/benchmarks/glove/glove.6B.300d.txt \
  --output "runs/$RUN_ID" --device cuda > "runs/$RUN_ID.log" 2>&1 < /dev/null &
echo "PID=$! LOG=runs/$RUN_ID.log OUTPUT=runs/$RUN_ID"
```

`tail -f runs/bilstm-YYYYMMDD-HHMMSS.log`로 진행 상황을 본다. 기본값은 4개 설정 × 3 seed, 각각 분류 20 epoch, CL 조건만 3 epoch를 추가한다. 설정별 평균과 동일 seed의 차이는 `summary.json`, 설정 및 파일 해시와 GloVe 단어 커버리지는 `protocol.json`에 저장된다. test를 읽지 않으며 자동 재개도 지원하지 않는다. 기존 폴더를 덮어쓰지 않는다. 작은 파이프라인 점검은 별도의 output으로 `--epochs 1 --cl-epochs 1 --seeds 13`을 추가한다.

어휘 목록에는 학습 및 검증 텍스트를 사용해 검증 단어의 사전학습 벡터를 불러온다(검증 라벨로 학습하지 않음). GloVe에 없는 단어는 무작위 초기화되며 특히 검증 전용 단어는 supervised 학습을 받지 못한다. BiLSTM과 BERT는 사전학습·모델 크기·토큰화·학습 설정이 다르므로 백본 구조만의 인과 효과는 분리되지 않는다. PANIC 재현이 아니며 CL에는 추가 학습량이 있다. 기존 test는 이미 탐색에 사용됐으므로 독립 최종 평가로 사용할 수 없다.

## Claude Haiku와 검증셋 비교

`claude_baseline.py`는 Anthropic Messages API를 사용하여 각 dev 행을 한 번씩 분류한다. 학습 데이터에서 라벨별 하나씩 고정 seed로 고른 예시만 프롬프트에 넣는다. dev 정답은 API에 보내지 않으며 평가 계산에만 사용한다. 12개 라벨은 이름이 모호하므로 예시 선정과 프롬프트가 결과에 영향을 준다. 실험은 지도 fine-tuning 모델과 few-shot 프롬프트 모델의 비교이며 동일 학습량 비교가 아니다. 모델의 학습 데이터에 벤치마크 노출이 있었는지는 알 수 없다. test는 읽지 않는다.

```bash
cp -n .env.example .env
chmod 600 .env
nano .env
```

`ANTHROPIC_API_KEY=YOUR_API_KEY_HERE`의 오른쪽만 본인의 키로 바꾼다. 키를 채팅이나 Git에 올리지 않는다. `.env`는 Git에서 제외된다. 모델 기본값은 Anthropic API의 `claude-haiku-4-5-20251001`이고 `.env` 또는 `--model`로 바꿀 수 있다. Claude Pro/Max 구독과 별개인 API 계정 및 크레딧이 필요하다.

먼저 30건 계획만 출력한다. 이 명령은 API 호출이 없고 키도 필요 없다.

```bash
python scripts/claude_baseline.py --output runs/haiku-pilot
```

계획상 호출 횟수 및 입력 문자 수는 토큰 수나 비용이 아니다. [Anthropic 요금표](https://platform.claude.com/docs/en/about-claude/pricing)를 확인한다. 전체 dev는 1,619번의 유료 요청을 보낸다. `--max-tokens 32`는 한 요청의 출력 상한이고 입력 및 재시도 비용을 포함한 총액 상한은 아니다. 실패하거나 timeout인 요청은 서버 처리 여부를 알 수 없어 재시도 시 중복 청구가 가능하다. 이메일, 제품 데이터 등 공개 권한이 없는 데이터를 무심코 API에 전송하지 않는다.

```bash
python -u scripts/claude_baseline.py --output runs/haiku-pilot --run
```

pilot은 dev의 앞 30건으로 대표 표본이 아니며 전체 학습 모델 점수와 직접 비교하면 안 된다. 시험한 뒤 전체 검증셋 실행:

```bash
mkdir -p runs
RUN_ID="haiku-$(date +%Y%m%d-%H%M%S)"
nohup python -u scripts/claude_baseline.py --limit 0 \
  --output "runs/$RUN_ID" --run \
  --compare runs/controls-20261029-162218/summary.json runs/bilstm-20261030-142340/summary.json \
  > "runs/$RUN_ID.log" 2>&1 < /dev/null &
echo "PID=$! LOG=runs/$RUN_ID.log OUTPUT=runs/$RUN_ID"
```

`--compare`에는 실제 서버에 있는 기존 결과 파일을 지정한다. 생략해도 Haiku 평가는 가능하며, 파일이 없거나 dev 해시가 다르면 유료 호출 전에 중단된다. 각 요청 결과는 `predictions.jsonl`에 즉시 기록되며, 실패 후 `--resume`을 기존과 같은 `--limit`, `--output` 및 기타 설정으로 추가하면 기록된 ID는 재호출하지 않는다. API가 응답을 처리한 직후 로컬에 저장되기 전에 중단된 경우는 예외다. 각 라벨 밖의 응답도 기록하고 오답으로 계산하며, 실패 결과를 제외하지 않는다. 요청별 사용 토큰 수를 저장하지만 비용을 청구서와 동일하다고 보장하지 않는다.
